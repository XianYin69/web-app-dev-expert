# evidence-rule — 不许虚构数字

## 必须

1. 任何性能、容量、延迟、命中率、体积数字，必须来自**本机实测**或**引用来源**，
   并附产生它的方法：探针命令、仪表盘名、规范条款链接。
2. 未测量的数字一律标注为 `assumed`（假设）或 `unknown`（未知），
   并说明如何测得：`scripts/` 内对应探针见 [scripts](../scripts/scripts.md)。
3. 现场指标（field data）与实验室指标（lab data）分开陈述，不得互相冒充；
   Core Web Vitals 阈值判定以 p75 现场数据为准。
4. 给出优化建议时，说明预期影响的**量级来源**（例如「阻塞渲染的请求数 −1」），
   而不是承诺一个凭印象的毫秒数。
5. 引用外部规范时保留版本号与日期（见 [references](../references/references.md)
   的 2026-10-07 核验记录）。

## 禁止

- 编造「通常能提升 30%」这类无来源百分比。
- 把示例配置里的数字当成用户环境的实测值。
- 用「业界最佳实践」掩盖未验证的事实判断。
- 在探针失败/网络不可达时，用猜测填补输出 —— 应如实报告受阻
  （见 [resistance](resistance.md) 降级策略）。

## 记录格式

结论后附一行证据行，例如：

```
evidence: python -B scripts/sample_web_vitals.py --url <url> --runs 5  (2026-10-07)
```

无法给出证据行时，把该句改写为假设或未知。

## 违反后果

虚构指标会直接误导容量规划、SLA 承诺与回滚阈值设定，
且事后无法追溯哪些数字是假的 —— 故列为红线。
